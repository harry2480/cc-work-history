# CC Work History フロントエンド規約

Electron renderer + React 18 + shadcn/ui + Tailwind CSS におけるフロントエンド規約。

---

## ディレクトリ構成

`apps/desktop/src/renderer/` 配下:

| ディレクトリ | 責務 |
|---|---|
| `pages/` | 画面（メイン／ダッシュボード／セッション一覧／設定）。features を組み合わせるだけ |
| `features/` | 機能別モジュール（timeline, session-detail, dashboard, session-list, filters, settings） |
| `components/` | 機能をまたいで使う React コンポーネント |
| `components/ui/` | shadcn/ui コンポーネント |
| `hooks/` | 機能をまたいで使うカスタム hooks |
| `lib/` | renderer 側の util（日付計算、色割り当てなど） |
| `stores/` | Zustand ストア |
| `../main/backend/` | main プロセスの構造（`アーキテクチャ.md` 参照）。renderer から import しない |

---

## renderer と main の分離

- **renderer は Node.js API・ファイルシステム・子プロセスに直接アクセスしない。** 必要なデータはすべて `window.api`（preload が公開）経由で取得する
- BrowserWindow は `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true` で生成する
- `window.api` の型は `src/shared/ipc-contract.ts` から導出する。renderer 側で独自に型を書かない
- main 側のドメインモデルを renderer に渡さない。IPC では DTO（プレーンなオブジェクト）だけをやり取りする

---

## データフローと状態管理

- **状態管理**: Zustand は UI の状態（表示中の週、ズーム倍率、選択中のセッション、色分けの基準、フィルタ条件）にだけ使う。セッションデータそのものはストアに複製しない
- **データフェッチ**: 各 feature の `api/` で `window.api` をラップしたフックを用意し、コンポーネントからはそのフック経由で取得する
- **リアルタイム更新**: main からのプッシュ通知（セッション追加・更新）を購読し、該当する期間のデータを取り直す。ポーリングはしない
- **ミューテーション**: 概要・タグの編集、セッション再開、設定変更は `window.api` の action 系メソッドを呼ぶ。成功後に関連データを取り直す
