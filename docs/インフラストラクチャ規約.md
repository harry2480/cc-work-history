# CC Work History インフラ規約

pnpm workspace + Electron（electron-builder）+ SQLite（better-sqlite3）で構成する、ローカルアプリのインフラ構成と規約。サーバー・クラウドは使わない。

---

## Monorepo 構成

pnpm workspace で管理する。`apps/` 配下に各アプリケーションを配置する。

```text
cc-work-history/
├── apps/
│   └── desktop/             # Electron アプリ
│       ├── src/
│       │   ├── main/        # main プロセス（DDD 4層）
│       │   ├── preload/     # contextBridge
│       │   ├── renderer/    # React UI
│       │   └── shared/      # IPC 型定義
│       ├── test/
│       └── electron-builder.yml
├── pnpm-workspace.yaml
├── biome.json               # 共有 lint/format 設定
└── package.json             # workspace scripts
```

## ビルド・配布

| 種別 | トリガー | 方法 | 備考 |
|---|---|---|---|
| ローカル開発 | `pnpm dev` | Vite の dev サーバー + Electron 起動 | renderer は HMR、main は変更時に再起動 |
| CI 検証 | PR 作成 / 更新、push | GitHub Actions で `pnpm verify` | ubuntu-latest |
| リリースビルド | タグ push（想定） | electron-builder で各 OS 向けにパッケージ | macOS / Windows / Linux |

### electron-builder 設定

- 対象 OS: macOS（dmg）/ Windows（nsis）/ Linux（AppImage）
- Build Command: `pnpm build`（Vite で main / preload / renderer をビルド）→ `electron-builder`
- Install Command: `pnpm install`
- ネイティブモジュール: better-sqlite3 は Electron の Node ABI に合わせて再ビルドする（`electron-builder install-app-deps`）
- コード署名・公証（macOS notarization）は配布方法が決まった時点で設定する

## データ保存

- **DB ファイル**: `app.getPath('userData')` 配下の SQLite ファイル。リポジトリ・ログディレクトリには置かない
- **マイグレーション**: `src/main/backend/infrastructure/db/migrations/` に連番の SQL を置き、起動時に `PRAGMA user_version` を見て未適用分を順に適用する
- **キャッシュの扱い**: DB は JSONL の解析キャッシュであり、正のデータは `~/.claude/projects/` 側にある。DB を削除しても再解析で復元できること（手動編集した概要・タグは除く）
- **ローカル開発**: 開発時は `userData` を本番と分け、開発用 DB で本番データを壊さない

---

## 外部依存・ネットワーク

- 外部ネットワーク通信は行わない。Claude CLI の子プロセス呼び出しのみ例外とする（通信は CLI 自身が行う）
- 自動アップデートなど通信を伴う機能を足す場合は、要件定義の「完全ローカル」方針と照らして別途判断する
- 環境変数で Stub 実装に切り替えられるようにし、Claude CLI・git がない環境でもテストと開発ができるようにする
