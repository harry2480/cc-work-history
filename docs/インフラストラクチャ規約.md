# CC Work History インフラ規約

pnpm workspace + Electron（electron-builder）+ SQLite（better-sqlite3）で構成する、ローカルアプリのインフラ構成と規約。サーバー・クラウドは使わない。

---

## Monorepo 構成

pnpm workspace で管理する。`apps/` 配下に各アプリケーションを配置する。

```text
cc-work-history/
├── apps/
│   └── desktop/             # Electron アプリ
│       ├── src/
│       │   ├── main/        # main プロセス（DDD 4層）
│       │   ├── preload/     # contextBridge
│       │   ├── renderer/    # React UI
│       │   └── shared/      # IPC 型定義
│       ├── test/
│       └── electron-builder.yml
├── pnpm-workspace.yaml
├── biome.json               # 共有 lint/format 設定
└── package.json             # workspace scripts
```

## ビルド・配布

| 種別 | トリガー | 方法 | 備考 |
|---|---|---|---|
| ローカル開発 | `pnpm dev` | Vite の dev サーバー + Electron 起動 | renderer は HMR、main は変更時に再起動 |
| CI 検証 | PR 作成 / 更新、push | GitHub Actions で `pnpm verify` | ubuntu-latest |
| パッケージビルド | `pnpm dist`（手元で実行） | electron-builder で各 OS 向けにパッケージ | 署名なし。CI での配布はしない |

### electron-builder 設定

設定は `apps/desktop/electron-builder.yml`。**署名なしのローカルビルドのみ**とする（Issue #42 の決定）。

- 対象 OS: macOS（dmg）/ Windows（nsis）/ Linux（AppImage）
- コマンド: `pnpm dist`（実行中の OS 向け）、`pnpm dist:mac` / `pnpm dist:win` / `pnpm dist:linux`（OS 指定）。中身は `electron-vite build` → `electron-builder`
- 出力先: `apps/desktop/release/<version>/`（`.gitignore` 済み、コミットしない）
- 同梱物: `out/`（electron-vite のビルド結果）と `package.json`、実行時に必要な `dependencies` のみ。`src/`・`test/`・フィクスチャ・`docs/` は含めない。SQL マイグレーションは `import.meta.glob` で `out/main/index.js` に埋め込まれる
- ネイティブモジュール: better-sqlite3 は N-API の prebuild（`prebuilds/<platform>-<arch>.node`）を同梱しており Electron の ABI に依存しないため、再ビルドしない（`npmRebuild: false`）。ビルド対象以外の prebuild は除外し、`.node` は `asarUnpack` で asar の外に展開する
- アイコン: 未設定のため Electron の既定アイコンになる。用意する場合は `apps/desktop/build/` に置く
- コード署名・公証（macOS notarization）・GitHub Releases などへの公開・CI での配布ジョブは行わない。`publish: null` でアップロードを無効化しており、secret も不要
- 署名なしのため、macOS では初回起動時に Gatekeeper の警告が出る（Finder で右クリック →「開く」）。Windows では SmartScreen の警告が出る
- アーキテクチャ: macOS は実行中の Mac の CPU 向け、Windows / Linux は x64 向けにビルドする
- 他 OS 向けのビルドは、その OS 上で実行するのが確実（macOS 上での Windows / Linux 向けビルドは保証しない）。Apple Silicon の Mac では、NSIS・AppImage のビルドツールが x64 バイナリのため Rosetta 2 がないと失敗する
- パッケージ版の動作確認では `CC_WORK_HISTORY_USER_DATA_DIR`（一時ディレクトリ）と `CC_WORK_HISTORY_STUB_LOGS=true` または `CC_WORK_HISTORY_LOG_DIR`（フィクスチャのコピー）を指定し、本番のデータ・ログに触れない

## データ保存

- **DB ファイル**: `app.getPath('userData')` 配下の SQLite ファイル。リポジトリ・ログディレクトリには置かない
- **マイグレーション**: `src/main/backend/infrastructure/db/migrations/` に連番の SQL を置き、起動時に `PRAGMA user_version` を見て未適用分を順に適用する
- **キャッシュの扱い**: DB は JSONL の解析キャッシュであり、正のデータは `~/.claude/projects/` 側にある。DB を削除しても再解析で復元できること（手動編集した概要・タグは除く）
- **ローカル開発**: 開発時は `userData` を本番と分け、開発用 DB で本番データを壊さない

## 外部依存・ネットワーク

- 外部ネットワーク通信は行わない。Claude CLI の子プロセス呼び出しのみ例外とする（通信は CLI 自身が行う）
- 自動アップデートなど通信を伴う機能を足す場合は、要件定義の「完全ローカル」方針と照らして別途判断する
- 環境変数で Stub 実装に切り替えられるようにし、Claude CLI・git がない環境でもテストと開発ができるようにする
