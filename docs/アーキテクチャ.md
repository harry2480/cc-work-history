# CC Work History アーキテクチャ設計規約

pnpm workspace + Electron（main / preload / renderer）で構成する。そのうち main プロセスのバックエンドに適用する DDD 設計規約。
`apps/desktop/src/main/backend/` 配下に適用する。

---

## プロセス構成

| プロセス | ディレクトリ | 責務 |
|---|---|---|
| main | `src/main/` | ログ解析、ファイル監視、SQLite アクセス、Claude CLI 呼び出し。DDD 4層を置く |
| preload | `src/preload/` | `contextBridge` で renderer に型付き API（`window.api`）を公開する。ロジックは持たない |
| renderer | `src/renderer/` | React UI。Node.js API・ファイルシステムには直接アクセスしない（`フロントエンド規約.md` 参照） |
| shared | `src/shared/` | IPC チャンネル名と、引数・戻り値の DTO 型。型と定数のみ置く |

---

## ディレクトリ構成

```text
src/main/backend/
├── domain/
│   ├── models/          # ドメインモデル（project, session, tag, activity, session-result）
│   ├── services/        # ドメインサービス（例: アイドル時間によるセッション区間分割）
│   ├── gateways/        # Gateway interface（ログ読み取り、ファイル監視、Claude CLI、git）
│   └── repositories/    # Repository interface
├── application/
│   └── usecases/        # ユースケースオーケストレーション
├── infrastructure/
│   ├── adapters/        # Gateway 実装（JSONL パーサ、chokidar、Claude CLI、git）＋ Stub
│   ├── repositories/    # Repository 実装（better-sqlite3）
│   └── db/              # SQLite 接続・マイグレーション
└── presentation/
    ├── composition/     # Composition Root（DI 組み立て）
    ├── loaders/         # データ取得（読み取り専用の IPC ハンドラ）
    ├── actions/         # 副作用（更新系の IPC ハンドラ）
    └── events/          # main → renderer へのプッシュ通知（セッション更新など）
```

---

## DDD 4 層構造

| 層 | ディレクトリ | 責務 |
|---|---|---|
| presentation | `presentation/composition/` `loaders/` `actions/` `events/` | `ipcMain.handle` / `webContents.send` を介した renderer との接続 |
| application | `application/usecases/` | ユースケースのオーケストレーション。ログ取り込み、概要・タグ生成プロンプトの組み立てと応答のパースを含む |
| domain | `domain/models/` `services/` `gateways/` `repositories/` | ビジネスルール。外部依存なし（Electron・Node.js API も参照しない） |
| infrastructure | `infrastructure/adapters/` `repositories/` `db/` | Gateway / Repository の実装。ファイルシステム・SQLite・子プロセスへの接続 |

---

## 依存方向（厳守）

`presentation → application → domain ← infrastructure`

- **domain は最内層。** 他層への依存禁止
- **application は domain にのみ依存。** infrastructure への直接依存禁止（Gateway interface 経由）
- **infrastructure は domain/gateways, domain/repositories に依存。** interface を implements する
- **presentation/loaders, actions, events は application + presentation/composition にのみ依存。** domain・infrastructure の直接参照禁止
- **presentation/composition は全層を参照可。** UseCase と infrastructure 実装を組み立てる唯一の場所
- **renderer** (`src/renderer/`) **は main のコードを import しない。** `src/shared/` の型と preload が公開する `window.api` のみに依存する

---

## presentation 層: composition / loaders / actions / events

Electron の IPC と DDD をつなぐ唯一の接続点。**renderer から main へのアクセスはすべて `src/shared/ipc-contract.ts` で定義したチャンネル経由とする。**

| 種別 | 責務 | 呼び出し元 |
|---|---|---|
| composition | UseCase と infrastructure 実装を組み立てる（Composition Root） | loader, action, events, `src/main/index.ts` |
| loader | データ取得（読み取り専用）。`ipcMain.handle` で登録する | renderer（`window.api.*` 経由） |
| action | 副作用（概要・タグの手動編集、セッション再開、設定変更など） | renderer（`window.api.*` 経由） |
| events | ファイル監視で検知した変更を renderer にプッシュする | ファイル監視 UseCase のコールバック |

- **preload はチャンネルを呼ぶだけ。** ロジック禁止
- **loader / action は composition から UseCase を取得して呼ぶ。** infrastructure の直接 import 禁止
- **IPC の引数は loader / action の入口で検証する。** renderer からの入力は信頼しない
- **composition は全層を参照してよい唯一の場所。** UseCase に infrastructure 実装を注入し、エクスポートする

---

## ドメインモデル設計

**Rich Domain Model を徹底する。Anemic Domain Model 禁止。**

- 値の生成・検証・変換はモデル自身のファクトリメソッド / インスタンスメソッドで行う
  - 例: `Session.fromLogEntries()` がログ行からセッションを組み立て、開始・終了時刻、トークン数、ステータス（進行中／完了）を確定する
- ドメイン不変条件はファクトリメソッド / コンストラクタで強制する。不正な状態のオブジェクト生成を許さない
  - 例: 終了時刻が開始時刻より前のセッション、空文字のタグ名は生成できない
- domain service に置くのは「複数モデルの協調」のみ。単一モデルで完結するロジックをサービスに書かない
- domain 層のエラーは `Result<T, E>` で返す。application / infrastructure 層は throw する

---

## サービス実装規約

**全サービス（domain service, UseCase）はクラスベース + コンストラクタ DI。関数エクスポートによるサービス実装は禁止。**

- コンストラクタの `private readonly` パラメータで Gateway 等の依存を受け取る
- ビジネスロジックは `execute()` 等の public メソッドで公開する
- ヘルパーは private メソッドに閉じる。クラス外への export 禁止

例外: 型定義 (`interface`, `type`) およびユーティリティ型 (`Result<T, E>` 等) は関数 / 定数エクスポート可。

---

## Gateway / Repository パターン

| 種類 | interface 配置 | 実装配置 |
|---|---|---|
| Gateway | `domain/gateways/` | `infrastructure/adapters/` |
| Repository | `domain/repositories/` | `infrastructure/repositories/` |

### 主な Gateway

| Gateway | 本番実装 | Stub 実装 |
|---|---|---|
| セッションログ読み取り | `~/.claude/projects/` 配下の JSONL を読む | 固定のフィクスチャを返す |
| ログ監視 | chokidar で変更を検知する | 手動でイベントを発火する |
| 概要・タグ生成 | Claude CLI を子プロセスで呼ぶ | 固定の概要・タグを返す |
| 成果取得 | `git` コマンドでコミット数・変更ファイル数を集計する | 固定値を返す |
| セッション再開 | ターミナルで `claude -r <sessionId>` を起動する | 呼び出しを記録するだけ |

- 外部プロセス・ファイルシステムに触れる Gateway は必ず Stub 実装を用意し、composition で環境変数に応じて切り替える
- Claude CLI が見つからない環境でも、概要生成以外の機能は動作させる
