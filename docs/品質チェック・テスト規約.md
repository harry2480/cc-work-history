# CC Work History 品質チェック規約

`vitest` + `TypeScript` + `dependency-cruiser` によるコード品質チェック規約。

---

## Quality Check 一覧

| チェック | ツール | 対象 | コマンド |
|---|---|---|---|
| Unit テスト | Vitest | domain, application, renderer の lib | `pnpm test:unit` |
| Integration テスト | Vitest | infrastructure（SQLite・JSONL 解析・ファイル監視） | `pnpm test:integration` |
| E2E テスト | Playwright（Electron） | 起動〜主要画面のフロー | `pnpm test:e2e` |
| 型チェック | `tsc --noEmit` | 全ソース（main / preload / renderer / shared） | `pnpm typecheck` |
| 依存方向チェック | dependency-cruiser | 全ソース | `pnpm depcruise` |
| リンター / フォーマッター | Biome | 全ソース | `pnpm lint` |

### verify コマンド実行フロー

`pnpm verify` は以下の順序で実行されることを期待する：

1. lint
2. typecheck
3. unit test
4. depcruise

コード変更後は必ず実行し、全パスすることを確認する。

---

## 型チェック (TypeCheck)

- `tsc --noEmit` で型エラーがないことを確認する
- **`any`** の使用は原則禁止（一時的な回避にはlint抑制コメントを明確に併記する）
- IPC の型は `src/shared/ipc-contract.ts` を唯一の定義元とし、main と renderer の型がずれないようにする
- CI で必ず実行。型エラーがある PR はマージ不可とする

---

## 依存方向チェック (Dependency Cruise)

- `アーキテクチャ.md` で定義された依存方向（presentation → application → domain ← infrastructure）をチェックする
- 加えて以下を禁止ルールとして設定する
  - `src/renderer/` から `src/main/` への import
  - `src/renderer/` から Node.js 組み込みモジュール（`fs`, `child_process` など）への import
  - `domain/` から `electron`・Node.js 組み込みモジュールへの import
- 違反があった場合、モジュールの切り出し・配置を見直す
