# CC Work History スタイルガイド

Tailwind CSS（+ shadcn/ui）に関するプロジェクト共通のスタイルルール。

## アプリシェルの高さ: 画面全体は固定し、内部でスクロールする

### ルール

- アプリシェルのルート要素は `h-dvh` + `overflow-hidden` にする（`h-screen` / `min-h-screen` は使わない）
- タイムライン・詳細パネルなどのスクロール領域は、親を `flex` にしたうえで `min-h-0`（横方向は `min-w-0`）+ `overflow-auto` を付ける
- ページ全体（`body`）をスクロールさせない

### 理由

メイン画面は「左: タイムライン、右: 詳細パネル」の 2 ペイン構成で、それぞれ独立してスクロールする。flex の子要素は既定で `min-height: auto` のため、`min-h-0` がないと中身に押し広げられてスクロールせず、ウィンドウ全体がはみ出す。

### クラスの使い分け

| 用途 | Tailwind クラス | 説明 |
|----------|----------------|------|
| アプリシェル | `h-dvh overflow-hidden` | ウィンドウ高さに固定 |
| 2 ペインの親 | `flex min-h-0 flex-1` | 残りの高さを埋める |
| スクロール領域 | `min-h-0 overflow-auto` | 自分の中だけでスクロールする |
| 横スクロール（タイムライン） | `min-w-0 overflow-x-auto` | ズーム時に横方向へスクロール |

### 具体例

```tsx
// NG
<div className="min-h-screen">
  <div className="flex">
    <Timeline />        {/* 中身が長いとウィンドウごと伸びる */}
    <DetailPanel />
  </div>
</div>

// OK
<div className="flex h-dvh flex-col overflow-hidden">
  <div className="flex min-h-0 flex-1">
    <div className="min-w-0 flex-1 overflow-auto"><Timeline /></div>
    <aside className="w-96 overflow-auto border-l"><DetailPanel /></aside>
  </div>
</div>
```

### 備考

Electron にはアドレスバーがないため `100vh` と `100dvh` の差は出にくいが、表記を統一するため `dvh` を使う。

## カラー: トークン経由で指定する

### ルール
- UI の色は shadcn/ui のテーマトークン（`bg-background`, `text-muted-foreground`, `border` など）を使う
- `text-[#333]` のように hex 値を直接書かない
- セッションバーの色（プロジェクト・タグ・ステータスごとの色）は `lib/config/` のパレット定義から割り当て、CSS 変数として渡す
- 色だけで情報を区別しない。進行中セッションは枠線やアイコンも併用する

### 理由
ライト／ダークテーマの切り替えと、設定画面での色変更を 1 か所の変更で反映させるため。

### 具体例
```tsx
// NG
<div className="bg-[#1a73e8] text-white">

// OK
<div
  className="bg-[var(--session-color)] text-[var(--session-foreground)]"
  style={{ '--session-color': palette.of(session.projectId).bg } as React.CSSProperties}
>
```

## タイムラインのバー配置: 位置とサイズだけ inline style を使う

### ルール
- セッションバーの `left` / `width`（ズーム時の座標）は計算値なので `style` で指定してよい
- それ以外の見た目（角丸、余白、文字サイズ、色）は Tailwind のクラスで指定する
- 座標計算は `features/timeline/utils/` の純粋関数で行い、コンポーネント内で計算しない

### 理由
動的な値をクラスで表現すると Tailwind が生成できないクラスになる。一方、見た目まで `style` に寄せるとテーマやトークンが効かなくなるため、範囲を限定する。

### 具体例
```tsx
// NG
<div className={`left-[${x}px] w-[${w}px]`} />          // ビルド時に生成されない
<div style={{ left: x, width: w, borderRadius: 4 }} />  // 見た目まで style に書いている

// OK
const { left, width } = toBarRect(session, viewport);
<div className="absolute h-6 rounded-sm text-xs" style={{ left, width }} />
```
