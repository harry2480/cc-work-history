# CC Work History 実装計画書

`要件定義.md` の「開発フェーズ（実装優先順位）」を、実際の作業単位に分けた計画。

## 1. 実施フェーズ

### Phase 0: プロジェクト基盤の移行
- 現在のリポジトリは Next.js 15 + Prisma（`apps/webapp/`）のスターター構成のため、要件定義の Electron 構成（`apps/desktop/`）へ移行する
- `CLAUDE.md`・`package.json` scripts・CI（`.github/workflows/`）・dependency-cruiser 設定を新構成に合わせる
- サンプル機能（joke）と Prisma 関連を削除する（Supabase・Vercel 関連は削除済み）

### Phase 1: MVP
- JSONL 解析とデータ保存
- 基本的なタイムライン表示（プロジェクト色分け）
- セッション詳細の基本表示
- ファイル監視による更新

### Phase 2: 自動サマリーと絞り込み
- Claude CLI による概要・タグの自動生成
- 色分け基準の切り替え
- フィルタ・検索機能

### Phase 3: 分析と周辺機能
- ダッシュボード
- 成果情報（コミット数・変更ファイル数）の充実
- 作業状況チェックリスト
- セッション再開・Markdown コピー・設定画面

## 2. 詳細実施計画

### 2.1 Phase 0: 基盤移行

| 作業 | 内容 |
|---|---|
| Electron 雛形 | `apps/desktop/` に main / preload / renderer / shared を作成し、Vite でビルドできるようにする |
| SQLite 導入 | better-sqlite3 を追加し、Electron 向けの再ビルド（`electron-builder install-app-deps`）を設定する |
| 品質チェック移行 | `pnpm verify` を lint → typecheck → unit test → depcruise に組み直す。renderer → main・Node.js 組み込みモジュールへの import 禁止ルールを追加する |
| CI 移行 | Postgres サービスと Prisma の手順を外す |
| ドキュメント | `CLAUDE.md` のアーキテクチャ・コマンド説明を新構成に更新する |

### 2.2 Phase 1: MVP

| 作業 | 層 | 内容 |
|---|---|---|
| ドメインモデル | domain | `Project` / `Session` / `Activity` モデル。ログ行からのセッション組み立てと不変条件 |
| ログ読み取り Gateway | domain / infrastructure | `~/.claude/projects/` の探索と JSONL のパース。壊れた行はスキップする。Stub 実装も用意する |
| DB スキーマ | infrastructure | `projects` / `sessions` / `activities` のマイグレーションと Repository |
| 取り込み UseCase | application | 全件取り込みと差分取り込み（更新日時またはファイルサイズで判定） |
| ファイル監視 | infrastructure / presentation | chokidar で変更を検知 → 差分取り込み → renderer に通知 |
| IPC | presentation / preload / shared | 週単位のセッション取得、セッション詳細取得、更新通知 |
| タイムライン UI | renderer | 週表示、プロジェクト色分けのセッションバー、進行中の強調 |
| 詳細パネル UI | renderer | 基本情報・状態の表示 |

### 2.3 Phase 2

| 作業 | 内容 |
|---|---|
| 概要・タグ生成 Gateway | Claude CLI を子プロセスで呼び出す。タイムアウト・CLI 未インストール時のフォールバック。Stub 実装 |
| 生成 UseCase | 生成のきっかけ（セッション更新後、一定時間の無操作）と多重実行の抑制。手動編集した概要は上書きしない |
| タグ | `tags` / `session_tags` のマイグレーションと Repository。手動編集 UI |
| 色分け切り替え | プロジェクト／タグ／ステータスの切り替えと凡例 |
| フィルタ・検索 | 期間・プロジェクト・タグでの絞り込み、概要の全文検索 |
| ズーム・パン | タイムラインの拡大縮小と横スクロール |

### 2.4 Phase 3

| 作業 | 内容 |
|---|---|
| ダッシュボード | 統計カード、日別グラフ、プロジェクト別サマリー（集計は SQL 側で行う） |
| 成果情報 | `session_results` テーブル。git からコミット数・変更ファイル数を集計する |
| チェックリスト | 作業状況チェックリストの表示（ログ中の TodoWrite の最後の状態を `session_todos` に取り込む。読み取り専用・手入力しない） |
| セッション一覧 | テーブル表示・ソート・フィルタ |
| セッション再開 | ターミナルで `claude -r <sessionId>` を起動する |
| Markdown コピー | 概要をクリップボードへコピーする |
| 設定画面 | データパスの確認、色設定、テーマ切り替え |
| 配布 | electron-builder で macOS / Windows / Linux 向けのパッケージを作る |

## 3. 未決事項

着手前、または該当フェーズの開始時に決める。

- セッションの「活動時間」の定義（最初と最後のメッセージの間か、一定時間以上の無操作で区間を分けるか）
- 自動概要生成を呼ぶタイミングと頻度（Claude CLI の利用量に影響する）
- 成果情報を取得する git リポジトリの特定方法（セッションの作業ディレクトリから辿る想定）
- `データモデル設計`（要件定義で参照されている別紙）の作成
- 配布方法（コード署名・公証の要否）

## 4. 完了条件

- 各フェーズの機能が要件定義の機能要件を満たしている
- `pnpm verify` が全てパスする
- Phase 1 完了時点で、実際の `~/.claude/projects/` のログを取り込み、タイムラインに表示できる
- 外部へのデータ送信が発生しない（Claude CLI の呼び出しを除く）
