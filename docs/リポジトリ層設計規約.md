# CC Work History Repository レイヤー設計方針

データベース（SQLite / better-sqlite3）への直接アクセスは `src/main/backend/infrastructure/repositories/` に集約します。
UseCase は `domain/repositories/` の interface を通してのみデータを操作し、loader・action から Repository を直接呼びません。

## 基本パターン

```typescript
// src/main/backend/infrastructure/repositories/sqlite-session.repository.ts
import type Database from 'better-sqlite3';
import { Session } from '../../domain/models/session.model';
import type { SessionRepository } from '../../domain/repositories/session.repository';

type SessionRow = {
  id: string;
  project_id: string;
  started_at: string;
  ended_at: string | null;
  // ...
};

export class SqliteSessionRepository implements SessionRepository {
  constructor(private readonly db: Database.Database) {}

  findById(id: string): Session | null {
    const row = this.db
      .prepare<[string], SessionRow>('SELECT * FROM sessions WHERE id = ?')
      .get(id);
    return row ? this.toModel(row) : null;
  }

  findByPeriod(from: Date, to: Date): Session[] {
    const rows = this.db
      .prepare<[string, string], SessionRow>(
        'SELECT * FROM sessions WHERE started_at < ? AND (ended_at IS NULL OR ended_at >= ?) ORDER BY started_at',
      )
      .all(to.toISOString(), from.toISOString());
    return rows.map((row) => this.toModel(row));
  }

  private toModel(row: SessionRow): Session {
    // 行 → ドメインモデルの変換は Repository 内に閉じる
  }
}
```

## 実装ルール

- **Repository はクラスで実装し、domain の interface を `implements` する。** DB 接続（`Database` インスタンス）はコンストラクタで受け取り、composition で注入する
- **DB 接続の生成（`new Database(path)`）とマイグレーションは `infrastructure/db/` に閉じ込める。** UseCase・loader・action から直接呼ばない
- **SQL は必ずプレースホルダ付きのプリペアドステートメントで書く。** 文字列連結でクエリを組み立てない
- **行 ↔ ドメインモデルの変換は Repository の private メソッドで行う。** snake_case の行型を Repository の外に出さない
- **複数テーブルにまたがる書き込みは `db.transaction()` でまとめる。** 例: セッション本体・タグ・活動イベントの一括取り込み
- Repository 関数は「DB クエリ実行 + 第一レイヤーのエラーハンドリング」のみを担当し、**複雑なビジネスロジックは呼び出し元（UseCase など）に残す**
  - 例外として、ダッシュボードの日別集計など、SQL で集計した方が明らかに速いものは Repository 側で実装してよい
  - DTO への変換は presentation 層で行う
- better-sqlite3 は同期 API のため、数千件規模の取り込みは main プロセスをブロックしないようバッチに分けて実行する
